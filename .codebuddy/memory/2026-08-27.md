## launchigniter Back 按钮点击不返回 → 加 history.back() 兜底
- 现象：`Clicking Back button.` 已打印、按钮绑定了 click，但没返回。原因：Next.js App Router / React 部分按钮的 click handler 依赖可信事件（`isTrusted===true`），程序 `.click()` 产生的合成事件 `isTrusted=false` 会被忽略；也可能 querySelectorAll 命中的是外层包裹 div（真正 handler 在内层子元素）。
- 修复：两个文件都在点击 Back 后轮询检测是否仍在 `/launch/*`（launchigniter.content 用 while 循环里 `await sleep(2000); if (isDetailPage()) history.back()`；launchigniterDetail.content 用独立 async 轮询最多 3s），仍在详情页就 `window.history.back()` 强制返回。SPA 软导航下 history.back() 必然回到列表首页。

## peerpush 卡片无 href，点击打不开 → monkey-patch window.open 捕获 URL
- 用户提供了 peerpush 真实卡片 DOM：`div.relative.cursor-pointer.group` 是**进度条上的产品图标**（img+排名奖杯），**内层/外层都没有 `<a href>`**（之前 curl 抓到的 `<a href="产品官网" target="_blank">` 是别的卡片类型）。所以 `card.querySelector("a[href]")` 返回 null，只能 `.click()`。
- `.click()` 打不开新标签的根因：站点靠 React onClick + `window.open(url,"_blank")` 打开，而程序化 `.click()` 是 `isTrusted=false`、**无 user activation**，被浏览器 popup blocker 拦截。
- 解法（已在 peerpush.content 实现）：向页面 MAIN world 注入 `<script>` monkey-patch `window.open`，把被调用的 url 写到 `<html data-peerpush-open="...">`（内容脚本 isolated world 能读 DOM 属性）；对卡片 `.click()` + dispatchEvent(pointerdown/mousedown/pointerup/mouseup/click) 触发 React onClick，读取捕获 URL 后用 `sendMessage(OPEN_TAB, url)` 走 background `tabs.create` 打开（绕开 popup blocker）。仍优先 `findDetailUrl`（自身/子级/父级 `<a href>`）。
- 关键认知：peerpush.net → peerpush.com 重定向，`?view=live` → `?view=race`（308）。matches 若用 `https://peerpush.net/?view=live` 可能在重定向后匹配不到。

## peerpush 最终方案：直接调 tRPC API，不走 DOM 点击
用户提供更优方案并采纳：peerpush 首页会 GET 调 `https://peerpush.com/api/trpc/product.publicFeed,...?batch=1&input={...}`，返回 JSON 里 `product.publicFeed` 的 `result.data.json.items[]` 含今天所有产品的 `websiteUrl`（真实官网）。
- **已验证 API 结构**：顶层是数组（7 项，对应各 procedure）；`product.publicFeed` 的 `result.data.json.items` 是对象数组（61 个产品），每项含 `websiteUrl/name/slug/tagline/logo` 等。取数路径不硬编码 index，遍历顶层数组找含 `items` 数组的那一项。
- 只请求单个 procedure 更干净：`https://peerpush.com/api/trpc/product.publicFeed?batch=1&input=%7B%220%22%3A%7B%22json%22%3A%7B%22view%22%3A%22race%22%2C%22racePeriod%22%3A%22day%22%7D%7D%7D`。
- peerpush.content 最终重写为：`matches` 改 `https://peerpush.com/*`；内容脚本直接 `fetch` API（同源，页面在 com 域）→ 遍历找 `items` → 提取全部 `websiteUrl` → 逐个 `await sendMessage(Message.SCRAPE_EMAILS, url)`（间隔 2s），带状态面板。完全绕开 DOM 点击/popup blocker/isTrusted 问题。
- 无 `Access-Control-Allow-Origin` 头：peerpush.com 页面同源 fetch OK；若脚本跑在 peerpush.net（重定向前）跨域会失败，故 matches 用 com。
- lint 0、typecheck 无报错。
